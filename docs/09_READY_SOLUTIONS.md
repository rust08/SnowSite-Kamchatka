# Готовые решения: что доступно и когда стоит подключать

## Уже встроено — без интернета

| Инструмент | Для чего | Состояние | Цена интеграции |
|---|---|---|---|
| Node.js 22+ (в тестах работает; CI Node 24) | HTTP, JSON, встроенный test runner | В package.json, npm install не нужен | Низкая |
| Leaflet (vendored из «Севера») | Карта, markers, Polyline, canvas | `public/vendor`; BSD-2-Clause | Уже используется |
| OSM city-network.json | Дорожная сеть | В архиве, ODbL, хеш | Уже используется |
| Собственный Dijkstra + heap | Направленные пути | `src/routing.mjs`, 4 теста | Уже используется |
| Статическая подложка Terrain WebP | Контекст рельефа | В архиве с attribution | Уже используется |

## Подключать только по необходимости, с proof-of-value

| Решение | Реальная роль | Условия / недостатки | Когда применять |
|---|---|---|---|
| **OR-Tools CP-SAT / MIP** | Дискретная оптимизация выбора и распределения | Python зависимость, размерность/время решения, лицензия компонентов, нужен мост Node↔Python | Когда есть small exact oracle и доказанный дефицит greedy |
| **SciPy `optimize.milp`** | MILP в Python | Отдельная среда, необходимость нормальной постановки матрицы/ограничений | Если простая задача без тяжёлой VRP |
| **NetworkX min-cost flow** | Линейная задача «объём → площадка» | Может неверно оценивать *фиксированную стоимость рейса*: решает релаксацию | Быстрая нижняя оценка/базовый план, чёткая оговорка |
| **Turf.js** | Геометрия, буферы, пространственные операции | npm зависимость, OSM не равен кадастровым слоям | После получения проверенных ГИС-слоёв |
| **PostGIS + QGIS** | Работа с множеством настоящих пространственных слоёв | Сервер, импорты, эксплуатация, геоданные | Когда уже есть реестр участков и документы |
| **OSRM / Valhalla / GraphHopper** | Routing engine + turn restrictions | Предобработка данных, профили грузовых авто и внешние ограничения, возможные расходы | Если текущий Dijkstra не отражает нужные манёвры и допуски |
| **MapLibre** | Больше управляемых картографических слоёв | Нужно tiles/style и источники, без карты может стать сложнее | Только если Leaflet перестаёт справляться |

## Принцип «build vs buy»

Codex перед добавлением зависимости должен зафиксировать: конкретную задачу, существующее решение, открытость источника, лицензию, системные требования Windows, размер скачивания, нужные ключи/оплату, офлайн fallback, тест производительности на нашем графе. Если можно решить в <100 строк без деградации корректности — сначала воспользоваться уже готовым локальным кодом.
