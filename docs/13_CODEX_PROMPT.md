# Готовый запрос для локального Codex App

Работаем над **новым независимым продуктом SnowSite-Kamchatka**, не над «Севером».

1. Открой эту папку как отдельный проект. Прочитай `AGENTS.md`, `docs/00_CODEX_START_HERE.md`, `docs/07_IMPLEMENTATION_PLAN.md`, `docs/08_ACCEPTANCE_TESTS.md` и нужные файлы из `src/`. Не читай весь архивный «Север».
2. Проверь `npm run check`, `npm test`, затем запусти `npm start`. Объясни по результатам, что уже работает. НЕ переписывай стартовый solver и карту, пока не проверишь их на контрольном сценарии.
3. Следуй приоритетам: воспроизводимость → корректные сценарные метрики → UX/UI → хороший README и demo → улучшения solver на тестах.
4. Если понадобится библиотека, ищи существующее решение и оцени лицензию, доступность для Windows, офлайн fallback и стоимость интеграции. Применяй её, если даёт доказуемую пользу; не создавай дополнительный backend ради одной функции.
5. Сохраняй юридическое разграничение: все начальные площадки, объёмы и скорости **сценарные**. Продукт не утверждает реальную допустимость земельного участка. Не выдавай эвристику за глобальный оптимум.
6. Нужен отдельный private GitHub `rust08/SnowSite-Kamchatka`, но не публикуй репозиторий без моего явного согласия. Если я уже создал его в браузере, проверь remote и сделай initial push только в новый репо, не в `Sever-GitHub`. Инструкция — `docs/10_GITHUB_SETUP.md`.
7. До завершения задачи: тесты, проверка браузера на ноутбуке, 3-минутный демонстрационный сценарий. Дай короткий отчёт «что готово / что осталось / какие допущения».

Главная задача: самостоятельный показываемый математический аналитический инструмент без зависимости от серверов основного «Севера».
