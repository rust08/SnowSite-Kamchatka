# Codex: стартовая инструкция (ПРОЧИТАТЬ ПЕРВОЙ)

## Цель и критерий завершённого результата

Создать **показываемый за 3 минуты** самостоятельный сервис **SnowSite**: карта города, сценарные точки образования снега, базовые площадки, кандидаты, сравнение пробега/рейсов/нераспределённого объёма при одинаковых условиях, объяснения и экспорт сценария. Визуально полноценный, численно проверяемый, не претендующий на юридическую или инженерную экспертизу.

## Уже сделано в комплекте

- Node HTTP API + JS frontend + Leaflet без установки npm-зависимостей.
- Реальная геометрия дорожного OSM-графа из «Севера», **не** реальные места складирования.
- Направленный Dijkstra туда/обратно, закрытия участков, baseline-vs-candidate, capacity + payload/density.
- Простой greedy solver и синтетический demo. Тесты маленьких графов.

Не строй замену всего этого без причины. Проверь, что стартует; веди изменения небольшими, проверяемыми порциями.

## Сразу при открытии проекта

1. `npm run check`, `npm test`, `npm start`.
2. Изучить `src/routing.mjs`, `src/optimizer.mjs`, `public/app.js`, `data/scenario.demo.json`.
3. Сверить документацию `01_PRODUCT_SCOPE`, `03_MATH_MODEL`, `04_ARCHITECTURE`, `08_ACCEPTANCE_TESTS`.
4. Если есть доступ к GitHub CLI: **предложить создание** отдельного private `SnowSite-Kamchatka` и выполнить с ведома пользователя. **Не создавать публичный репозиторий без запроса.** Подробно в `10_GITHUB_SETUP.md`.
5. Создать задачи по фазам; не пытаться за ночь превратить прототип в юридическую геосистему.

## Приоритеты Codex

**P0 — работающее демо:** корректный baseline, интерфейс, карта и статистика, no-data/invalid-data состояния; отсутствие смены данных baseline/variant; экспорт импорт.

**P1 — корректность:** маленький exact oracle для проверки greedy; случай, когда жадность ухудшает глобальную цель; статус неопределённости и недостаточной ёмкости; детерминизм. Улучшить solver только если тесты доказывают необходимость.

**P2 — расширения:** несколько новых площадок одновременно; очереди и смены, ограничения тяжёлой техники, CAPEX, интерактивная проверка условий земли, интеграции реальных источников — отдельные задачи, не обязательный Day-1.

## Перед завершением

- `npm run check && npm test` — зелёные.
- Один синтетический сценарий с 5 источниками, 2 базовыми площадками, 2 кандидатами.
- Одна проверка **направлений дорог**, закрытия и недоступной точки.
- Результат при нехватке вместимости сообщает нераспределённый объём и **не выдаёт уменьшение пробега за улучшение при другом объёме вывоза**.
- На карте видны точки и маршрут выбранного варианта; переключение не меняет исходный сценарий.
- README содержит запуск, скриншоты (если получены) и полный перечень ограничений.

**В финальном отчёте не утверждать**, что построен оптимальный полигон или сэкономлен бюджет города. Если фактических данных нет — модель сценарная.
