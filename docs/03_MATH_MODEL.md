# Математическая постановка и честные границы solver

## Граф и направления

`G=(V,E)`, `V` — дорожные узлы, `E` — направленные дуги; для `oneway=false` добавляется обратная дуга; `routable=false` и `closedEdgeIds` удаляются из графа. В весе — длина `km`.

Для каждой пары источник `i` / площадка `j` считаем два независимых кратчайших пути: `d_G(i,j)` и `d_G(j,i)`. При отсутствии хотя бы одного направления пара недоступна. **Отдельно:** OSM не гарантирует разрешённые повороты и тоннаж; MVP не выдаёт транспортный допуск.

## Спрос и рейсы

- `D_i` — объём снега на источнике в м³ (сценарный integer).
- `C_j` — свободная вместимость площадки в м³ (сценарная).
- `B` — объём кузова в м³, `P` — грузоподъёмность в кг, `ρ` — плотность снега в кг/м³.
- Предельная загрузка одного рейса `Q=min(B, floor(P/ρ))`, если `P` и `ρ` известны; при неизвестных P/ρ нельзя объявлять массу проверенной (в нашем демо они явные синтетические).
- Рейс из i в j: до Q м³, расстояние `d_G(i,j)+d_G(j,i)` (в том числе холостой возврат).

**Требуемая бухгалтерия:** сумма назначений из i ≤ D_i; сумма объёма на j ≤ C_j; единожды оплачивать каждую поездку; остаток каждого i объяснять.

## Целевая функция (для следующей версии)

Лексикографически:

1. `min sum_i unservedM3_i` при заданных мощностях.
2. Затем `min sum_{i,j,t} x_{ijt} (d_G(i,j)+d_G(j,i))` при том же объёме вывоза.
3. Опционально — `+ α * фиксированные затраты открытия площадки + β * время ожидания + γ * штраф за риск`, только когда эти параметры имеют достоверное определение и единицы.

Никакая оценка ₽ не эквивалентна фактически утверждённой стоимости: нужны договорные тарифы, затраты на погрузку, разгрузку, амортизацию, работу площадки, топливо и налоги.

## Сравнение сценариев

- `baseline`: те же источники, машины/вместимость, но только базовые площадки.
- `candidate_k`: тот же `baseline` плюс **один** кандидат k (его сценарная вместимость).
- Варианты сравнимы по пробегу **только при одинаковом обслуженном объёме**. Если объём разный — сначала показывать разницу `unservedM3`.
- При `baselineKm=0` процентное изменение `null`, не делить на ноль.
- Ранжирование по минимальному `unservedM3`, затем по `transportKm`, затем стабильный ID.
- Сценарии `candidate_1+candidate_2` одновременно — отдельный продуктовый режим, не включён в текущий рейтинг одиночных добавлений.

## Почему стартовый жадный solver нельзя называть оптимальным

`src/optimizer.mjs` сортирует источники по разнице расстояний до двух ближайших площадок и распределяет рейсы по доступным ближайшим площадкам. Он может уступать точному решению при ограниченной вместимости. **Это базовый эвристический результат, не гарантированная минимальная стоимость.**

Codex P1: добавить маленький `exact oracle` для ≤8 грузовых порций и ≤4 площадок с полным перебором/branch-and-bound, затем сравнить с greedy на фиксированных контрпримерах. Для большого случая выбирать алгоритм через метрики и ограничения, например min-cost flow в упрощённой линейной модели или MILP/CP-SAT через OR-Tools при необходимости; помнить что стоимость фиксированного рейса не линейна по объёму.

## Особая опасность ложных сравнений

Если A обслужил 100 м³ и проехал 200 км, а B обслужил 20 м³ и проехал 50 км, нельзя писать «B эффективнее на 75%». Алгоритм обязан вывести 80 м³ необслуженного объёма.
