## Порядок работы следующего агента
1. В актуальном репозитории прочитать `AGENTS.md`, последние записи `docs/17_HANDOFF_SESSION_LOG.md`, затем этот файл и `01_AUDIT.md`. Сверить коммит, рабочее дерево, уже сделанные изменения. Не повторять готовое.
2. Скопировать данный комплект в `docs/backend-review-2026-11-21/` (без вложенного `.git`); существующие файлы документации не заменять. Промпт — `02_CODEX_MASTER_TASK.md`. Точный контракт — `03_MODEL_AND_API.md`. Приёмка — `04_ACCEPTANCE_AND_PLAN.md`.
3. Запустить `npm test`, `npm run check`, `node <путь-к-пакету>/audit/reproduce.mjs <корень-SnowSite>`. Проверить результаты с текущим кодом. Для независимого MILP-эталона: `python audit/exact_demo.py` (использованы Python 3.13.5 + SciPy 1.17.0; установка в отдельное окружение, не обязательна для старого Node-сайта).
4. Начать с S0, затем S1–S3. Перед сменой агента обязательно обновить CHANGELOG, HANDOFF, тестовые результаты и остаток задач. Исходные числа v4.1.1 не перезаписывать: это baseline сравнения, не норматив будущих результатов.

## Что смотреть по задаче
- `01_AUDIT.md` — факты, дефекты, приоритеты, эксперименты.
- `02_CODEX_MASTER_TASK.md` — исполняемое задание (включает порядок и ограничения).
- `03_MODEL_AND_API.md` — предметная модель, математическая постановка, контракт API, k-best, пригодность, архитектура.
- `04_ACCEPTANCE_AND_PLAN.md` — конкретные тесты, правила остановки и бюджет разработки.
- `05_CONTINUITY_AND_CHANGELOG.md` — состояние на старте, правила памяти, документации и передачи между агентами.
- `templates/` — копируемые шаблоны задач, журнала изменений и решений.
- `audit/` — замороженные контрпримеры, независимый перебор с целыми объёмами, матрица демо, эталон MILP, логи выполнения.

## Решение продукта
Две существующие площадки и две будущие — исходное сообщение команды, не верифицированный реестр объектов. Вход конфигурируем. Нужны координаты точек въезда, доступная ёмкость и горизонт; ничего не выдумывать. Для демонстрации — синтетические кандидаты на реальном дорожном графе.

Цель — **получить крупный самостоятельный вычислительный модуль выбора и сравнения конфигураций площадок**, пригодный и как отдельный сайт, и для подключения к другому сервису. Отдельный интерфейс можно оставить минимальным, но API и модель должны быть стабильными и тестируемыми.
