## P0 / требуется обязательно

1. Зафиксировать невоспроизводимые/ограниченные места: F-01–04, CRIT-01–03. Вынести проверку графа и сценария в общие функции, определённые лимиты. Сохранить 39/39 существующих тестов либо осознанно заменить только устаревший expected-baseline с объяснением; не ослаблять инварианты. Добавить независимый oracle для **некратных** объёмов и оба fixture из аудита.
2. Сделать точное решение распределения для фиксированной конфигурации. Использовать агрегированные целочисленные объёмы и число рейсов, лексикографическую цель: минимум необслуженного объёма, затем минимум суммарного пробега. Сохранить старую эвристику как baseline/fallback с явным статусом. Не заявлять global optimum для timeout/FEASIBLE. Сравнивать по неокруглённому внутреннему значению. На городском демо получить и независимо проверить значения из `audit/demo_exact.json` при той же модели.
3. Сохранить `compareSites` или совместимый `/api/compare`. Не использовать старый формат как источник истинного статуса оптимальности. Создать модульный вход `optimize` + версионированный HTTP API `/api/v1/optimize` по контракту. Новые solver, маршрутная матрица и сценарий должны тестироваться без браузера, базы, сети и файловых путей, зашитых в ядре. Время/память ограничить, не блокировать HTTP на долгих запросах. Никаких массивов миллионов рейсов.
4. Решить задачу выбора площадок на конечном наборе. Поддержать `fixed`, `optional`, `replacementGroup`, `excluded`, точное число новых, целевое количество активных, фиксированный baseline; расширить модели позже только при необходимости. Для реального кейса 2 fixed + ровно 2 new из N>=3; выдавать Top-K различных конфигураций. Поддержать режимы размещения с нуля, добавления, перемещения/замены и отключения. Отдельно считать каждое значение числа новых; если нет CAPEX и политики числа объектов, не выдавать один общий экономический оптимум.
5. Добавить повторное решение после отклонения конкретного кандидата или набора. Тот же сценарий, сеть, спрос, емкости, параметры, цель; изменяется только exclusion. Старые результаты сохранять. Blocking по документированному запрету, неизвестное — tentative/needs_review. Не считать санкционированными даже действующие условные объекты. Top-K не следует автоматически из сортировки одиночных кандидатов. При таймауте сообщать, что порядок приблизительный.

## Разумная реализация: не изобретай solver

В аудите успешно выполнен SciPy/HiGHS MILP для четырёх конфигураций. Рекомендуемый первый spike — **выделенный локальный Python-worker с SciPy `milp`**, если текущий репозиторий и Windows позволяют воспроизводимую установку. Второй вариант — OR-Tools CP-SAT на Python с целыми расстояниями. Установку проверить, версию закрепить, добавить CI и запуск; официальный статус solver и границы оптимальности передавать наружу. Для маленьких конфигураций exhaustive enumeration + независимый exact assignment достаточно; для большого набора — integrated MILP с бинарными переменными выбора или CP-SAT. Не использовать SciPy и OR-Tools одновременно в production без причины. Без зависимости — ограниченный точный oracle на маленьких примерах, существующая эвристика честно маркирована. Докажи выбор на тестах, не трать весь лимит на пакетный менеджер. `scipy.optimize.milp` (документация https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.milp.html) HiGHS wrapper, поддерживает time_limit и mip_rel_gap. CP-SAT https://developers.google.com/optimization/cp/cp_solver — целочисленные ограничения и OPTIMAL/FEASIBLE. Проверить лицензию, платформу и актуальные pinned versions. Не вводить внешнюю платную API-зависимость. Не скачивать заново городскую сеть.

## P1 / после работоспособного ядра

- Переносимость сети: универсальный validation/adapter, импорт нового graph snapshot через CLI/конфиг, версии/хеши/единицы/профиль; второй маленький граф в тестах. Дорожный граф и dataset-specific `tools/check-data.mjs` разделить. Кеш матрицы по графу, closures, profile и узлам. При большой выборке источники forward + reverse Dijkstra вместо полного поиска на каждую пару. Полные полилинии только по запросу.
- Каталог кандидатов: точка участка/границы отдельно от узла въезда; ручной shortlist из CSV/GeoJSON с provenance, расстоянием привязки, ёмкостью, периодом и screening. Автоматический набросок узлов/кластеров допустим как exploratory candidate generation, не как утверждённые участки. Если приблизительное отсечение каталога — статус restricted_search, а не global optimum.
- Документированная пригодность: статусы и источники, проверка запретов, дата редакции, причины отказа, роль. Ручное экспертное решение отдельное от solver; отсутствующие СанПиН/ПЗЗ/кадастр не превращать в разрешение. Оставить возможность вернуть следующий вариант на тех же условиях. Достоверность каждого поля сохранять.
- Упрощённый CLI и интеграционный README: загрузить JSON, получить JSON без GUI, как зарегистрировать граф и вызвать матрицу/оптимизатор, пример импорта в другой сервис. Версия API отдельно от UI. Конфигурации и результаты сохраняются JSON, не требуется полноценная база сейчас.
- Небольшая проверка совместимости сайта: старый демо-режим открывается, результат объяснён, legal status / solver status показывается. Если добавляется простое управление Top-K, не делать редизайн. Не усложнять UI ценой solver.

Используй все P0-тесты `04_ACCEPTANCE_AND_PLAN.md`. Не скрывай провал, таймаут, неполную проверку. После каждого законченного шага обнови `CHANGELOG.md`, `docs/STATUS.md`, `docs/HANDOFF.md`; исторический журнал дополни, не удаляй. Опиши пример вызова, результаты, известные ограничения. README должен давать практический старт. Перегенерируй манифест релиза, сохрани проверку хеша графа. Отчёт — изменённые файлы, тесты, контрольные метрики, открытые задачи, следующий конкретный шаг.

**Stop rule:** когда независимый solver, multi-site, topK + exclusion и API работают и проходят P0, закончи эту итерацию. Не начинай учёт реального автопарка, очередей, GPS, новые правовые интеграции, автоматическую генерацию полигонов по спутнику, фронтенд с нуля, CAPEX без данных. Если лимит заканчивается, оставь последний работающий коммит и точную передачу; не обещай того, чего не проверил.
