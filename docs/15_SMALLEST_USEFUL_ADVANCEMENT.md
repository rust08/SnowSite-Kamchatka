# Что стоит кодить после первого запуска: быстрые улучшения по ROI

Этот проект создаётся рядом с «Севером»; задача — не сжечь лимиты на переписывание старого planner.

## Кандидаты «наибольшая польза / малый риск»

1. **Реальная карта выбора (уже есть):** выбор кандидата кликом, явно подписанная сценарность.
2. **Пересчёт рейтинга с одинаковым спросом (уже есть):** сортировка по необслуженному объёму, затем километрам.
3. **Сохранение сценария (уже есть):** JSON экспорт и импорт.
4. **Валидация с конкретными ошибками:** добавить UI подсказывающие причины «нет обратного пути», «площадка заполнена», «не задан грузовой допуск».
5. **Локальная устойчивость:** debounced compare на больших графах, сохранение состояния при переключении вида таблица/карта.
6. **Small exact oracle:** даст математическую убедительность и поможет найти контрпримеры greedy, прежде чем внедрять сложный solver.
7. **Понятная диаграмма распределения объёмов по площадкам:** сколько рейсов, источники, исчерпание вместимости.

## Что не делать до пилота

- Новая система авторизации и сложная БД.
- Собственный GIS-движок, если Leaflet справляется.
- Сбор всех потенциальных земель Камчатки без кадастровых и гидрологических данных.
- Автоматическая загрузка погоды (не доказывает фактические объёмы снега).
- Интеграция со всеми внешними дорожными API до проверки конкретного ограничения.
- Генерация «настоящих полигонов» на основе только дорожных узлов.

## Осмысленный следующий технический milestone

На маленькой проверочной сети найти случай, где greedy хуже оптимума, после чего продемонстрировать, что новый solver уменьшает километраж при одинаковом вывезенном объёме и не ухудшает ограничения.
