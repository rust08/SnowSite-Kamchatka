## Что можно делать сейчас

R01–R05 — локальная стабилизация v4.10.1 по независимому аудиту. Результат, регрессии и передача на независимое ревью в [REVIEW_FIX_REPORT](../REVIEW_FIX_REPORT.md). До вердикта ревью не открывать новый этап; после передачи остановиться.


Локальная приёмка оставшихся измеримых критериев выполнена в v4.8.1; согласованная синхронизация интерфейса завершена в v4.9, UX-доводка по запросу владельца в v4.10 и точечные исправления R01–R05 в v4.10.1; новых незаблокированных согласованных implementation tasks не осталось. Не начинать новый GIS-модуль, исследование, изменение solver, редизайн, развёртывание или миграцию репозитория ради следующей версии. Следующее действие — посмотреть этот перечень с владельцем; открывать только выбранный существующий этап при снятии его блокера. Подтверждение реальной геометрии/ёмкости и техническая подготовка не равнозначны. Не считать неизвестные эксплуатационные значения нулевыми.

При исправлении конкретного обнаруженного дефекта — воспроизводимый тест, отдельный коммит, актуальные README/STATUS/HANDOFF/CHANGELOG/технические документы, release manifest; сохранить всю историю. Не обещать неограниченный SLA, правовой допуск или реальную экономию.

# План доводки SnowSite в отдельном репозитории

## Не смешивать задачи с «Севером»

Новый репозиторий — **SnowSite-Kamchatka**. Никаких правок в `rust08/Sever-GitHub`, общего хостинга и зависимости от `SNOW_DB_DIR`. Репозиторий рекомендуется **private** до проверки готовности к публикации и лицензий. Интервью остаются вне репо.

## Фаза A: воспроизводимый старт (уже готова, проверить)

- [x] Дорожный OSM-граф из текущего «Севера» встроен в `data/`, хеш проверяется `npm run check`.
- [x] Маршрутизация по направленным дорогам с закрытиями; обратный маршрут учитывается независимо.
- [x] Сценарные источники/площадки и грузовик.
- [x] Первичное сравнение baseline с отдельными кандидатами.
- [x] Отдельный frontend, без npm-зависимостей и внешних картографических API.
- [x] Исходные автоматические тесты; уточнить выполнение в среде пользователя.

## Фаза B: математическая честность и устойчивость (P0)

- [ ] Прогнать полный граф, сравнить с базовыми показателями `docs/08_ACCEPTANCE_TESTS.md`.
- [ ] Добавить точный маленький oracle (полный перебор / branch-and-bound для коротких задач) и детерминированные контрпримеры к regret-first greedy.
- [ ] Повысить качество baseline, чтобы он не становился искусственно плохим из-за порядка обхода demand; например, min-cost flow в линейном приближении или локальные перестановки и обмены рейсов. Каждая смена solver только с тестами.
- [ ] В выводе отдельно показать `served`, `unserved`, `km`, `trips`, основание для ranking, стоимость **только транспортная сценарная**.
- [ ] Сделать объяснения, если маршрута нет, вместимость исчерпана, недостаточен payload, узел вне дорожной сети.
- [ ] Зафиксировать стабильные ключи и версию сценария; roundtrip и входные данные не должны мутировать при сравнениях.

## Фаза C: сценарный UX, пригодный для публичного показа (P0)

- [ ] Простая навигация/дашборд, картографические точки, визуальные легенды, выбор варианта и подсветка маршрутов.

- [ ] Проверка в браузере: добавить кандидата, изменить вместимость, сравнить, перезагрузить или импортировать сохранённый сценарий.
- [ ] README: скриншот, быстрый старт Windows, 3-минутный сценарий демонстрации и известные ограничения.

## Планы, которые нельзя подменять фальшивым «готово»

**P1 после демонстрации:** сравнение нескольких новых площадок в одной комбинаторной задаче; честная оптимизация capacity+trip costs; ввод CAPEX и OPEX; очередь приёмки и смены; разные грузовые профили; дорожные ограничения по тоннажу и высоте; наблюдаемый спрос; проверка реальных площадок.

**P2 исследование:** кадастр/ПЗЗ, экологические ограничения, гидрология и геология; дорожные паспорта, GPS и учёт талонов. Не заявлять «подбор законного участка» до получения документального слоя.

## Stop conditions

Если внешняя библиотека не устанавливается или сеть отсутствует — сохраняем текущий офлайн baseline, пишем issue, а не блокируем демо. Если нет документированной вместимости — симуляция, а не «реальная эффективность». Если расчёт сильно тормозит на городском графе — измерить профиль до смены стека.
