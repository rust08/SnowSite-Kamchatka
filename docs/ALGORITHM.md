# Алгоритм v1

Первый раздел ниже фиксирует историческую модель S1; последующие разделы описывают расширения v4.3–v4.7. В v4.6 изменено только размещение модулей. С v4.8.1 математическая модель/solver не менялись; текущий план в 07_IMPLEMENTATION_PLAN.md.
Историческая эвристика `packages/optimization/legacy.mjs` не доказывает оптимум; новый solver `workers/milp-python/worker.py` решает fixed-charge transportation. Для пары i,j с двумя маршрутами L_ij = d(i,j)+d(j,i), единица мм, округление каждого направления как legacy audit. x_ij — целые м³, n_ij — целые рейсы, u_i — остаток. Сумма x по j + u_i = D_i; сумма x по i ≤ C_j; 1−Q ≤ x−Qn ≤ 0, значит n=ceil(x/Q), включая нулевой пробег. Недостижимые пары отсутствуют. Две стадии: min Σu, затем при доказанном минимуме min ΣLn. HiGHS MILP с mip_rel_gap=0, числовые допуски solver; независимый checker проверяет целочисленное назначение и objective. При таймауте не выдаём optimal. Sparse модель O(IJ) переменных и ограничений, NP-hard в общем случае. На этапе S1 matrix использовала legacy Dijkstra/cache по узлам, без loaded/empty различий; это историческое ограничение снято в S4.2/S4.3 (ниже). Время/стоимость — исключительно движение. Нет юридического подтверждения, реальных полигонов или CAPEX.

## Выбор площадок (S2)
Перебор допустимых бинарных наборов z (fixed / excluded / cardinality / replacement-group constraints), матрица одна на весь запуск, min U затем L для каждого набора. Ранжирование (U,L,JSON sorted IDs) — точный topK только после полного перебора и двух optimal стадий каждой конфигурации. Для 2+2 из N кандидатов число сочетаний C(N,2), в общем случае O(2^N) плюс MILP на каждое сочетание; pruning и пределы 100000 узлов, 1000 наборов на cardinality. При неполном покрытии ranking provisional/incomplete. Группа замены выбирает 0–1 или ровно 1 (lower/upper); её кандидатные места не считаются чистыми добавлениями. Frontier — отдельные ранжирования k; верхний search/alternatives отражает первый k, весь набор в frontier. Baseline — исходные existing, если screening их допускает, независимо от user exclusion; историческая ссылка не является разрешённым набором в новом поиске. Нельзя сравнивать км при различном обслуженном объёме. Не выводится экономически оптимальное число объектов.

## v4.3 safe selection
Opt-in preserve_existing preset fixes existing sites for add/frontier; relocate fixes existing outside explicit groups. Mathematical objectives, fixed solver and catalogue tie ordering unchanged. Zero same-node pair remains scenario-only and now warns. No legal or operational certification.

## S4.1 evidence/candidate boundary
The catalogue is not the mathematical input. Historical lead IDs are ineligible; explicit SiteRecord adapter checks provenance, scoped evidence and input assumptions. Conditional scenario access and capacity are explicit. At v4.3 the strict adapter rejected positive intra-site lengths; v4.4 adds an explicit full-roundtrip cost term (below). No legal/operational claims. Independent six-candidate oracle in tests/v43-catalog.test.mjs verifies all 15 active configurations and rank.

## S4.2 — new physical constraints
For a documented or explicitly scenario-only trip cap T_j add sum_i n_ij <= T_j; no cap row if null/absent, warn unknown. Check per-site trip counts independently of solver. Storage volume C_j and trip limit T_j are independent. Binding means equality in incumbent, not proof of root cause. Counterexample: D=30, Q=10, near C=100 T=1, two-way 2 km, far C=100 and two-way 6 km. New optimum 14 km (1 near, 2 far); near-only baseline leaves 20 m³. Counterfactual no trip limit serves all in 6 km. Site-type incompatibility removes pair only if type and acceptance known. Loaded/empty paths use separate closure sets (supplied blocked edges and validated gross/width thresholds); cost L=round(outward*1e6)+round(return*1e6) in mm. Full rated load is conservative, not load-dependent routing. Unknown road rules, access, snow acceptance, queue time are not certified. Same-node educational zero preserved with warning. Two-stage objective unchanged, no fabricated service time or financial effect.

## S4.3 distance matrix and remaining scale bottleneck
For D unique source nodes, S unique site nodes, take min(D,S) starts. Two directed trees per start, reverse the opposite leg's graph; distance-only, no predecessor arrays, bounded single-tree memory. Cost parity against old path reconstruction on city and synthetic directed graphs. Cache key includes graph snapshot, profiles, closures and snow type inputs; 8 matrices × at most 50×30, TTL 120s, single process. Existing enumeration remains the reference; benchmark 20×30 synthetic with 378 combinations and 5s budget proves 16, evaluates 17 (last may timeout), so ranking provisional. Historical v4.3 comparison; v4.4 implements integrated z-model and v4.7 proves bounded-enumeration Top-5 on this frozen dataset (below).

## v4.4 / S4.3a — optional unified facility selection
`policy.searchStrategy="unified_milp"` replaces *only the selection search*, not the historical baseline allocation. For each rank the existing sparse integer x,n,u model is extended by binary z_j. Bounds fix mandatory/excluded sites (evaluate fixes all nonmandatory to zero); storage Σ_i x_ij ≤ C_j z_j and receiving Σ_i n_ij ≤ T_j z_j when known. Because 1−Q ≤ x−Qn ≤ 0, x=0 implies n=0, including zero-cost pairs. Pairs incompatible with snow type or either directed route have already been removed by the common matrix. Cardinality rows cover pure new sites (not replacement members), active sites and each replacement group. `requireAllServed` fixes u_i=0 for alternatives only. For exact set A, no-good cut Σ_{j∈A} z_j − Σ_{j∉A} z_j ≤ |A|−1; supports empty set and does not ban subsets/supersets. Previously returned configurations are appended as cuts; no repeated allocations of the same set.

Rank is lexicographic min U, then min L with U pinned to its proved optimum, then min −Σ_j 2^(N−1−j) z_j at proved U,L, with IDs sorted in ascending raw JS string order. For JSON tokens preserving this order that tie objective exactly matches legacy `JSON.stringify(sortedIds)`: including the earliest differing ID precedes excluding it; a longer prefix precedes its shorter prefix because comma precedes closing bracket. No distance/tie weighting in a single objective; ≤30 sites, weights ≤2^29. For escape-sensitive IDs whose JSON-token ordering differs, explicitly fall back to bounded exact enumeration (warning), rather than misrank or change legacy semantics. The implementation divides unified distance coefficients by their integer GCD if nonzero and multiplies reported values/bounds back to mm. It does not round route distances beyond the existing matrix rounding. Numeric optimality is within HiGHS tolerances; checker recomputes actual integer volumes, trips, distance and tie objective and rejects mismatches in proven stages, also for a partial incumbent. Independent policy check checks membership, counts, exclusion and prior no-good sets.

One rank call contains up to three MILP stages; a rank is proved only after all three optimal, or an infeasible first stage proves exhaustion. K proved ranks suffice without solving each configuration; incomplete rank stops search and may return one checked incumbent after already proved prefix. `exact_top_k` only when all requested ranks proved or valid finite set exhausted with proved prefix; otherwise `provisional`/`incomplete`. Baseline and frontier semantics unchanged. Complexity: O(IJ+J) variables, O(IJ+I+J+groups+cuts) sparse entries plus up to N coefficients per set/cardinality cut; still NP-hard. No claim of asymptotic or guaranteed wall-clock speedup. Enumeration is default/reference. Benchmarks under v44 show 5s large case not yet fully proved; initial and rejected LP strengthening variants retained. See `docs/benchmarks/v44/acceptance.md`.

## v4.4 / A08a — explicit intra-site roundtrip term
Optional nonnegative R_j=`intraSiteRoundtripMm` is total internal motion per dump trip, in integer mm, once per trip (not per cubic metre and not twice). For a reachable compatible pair, L_ij = road_loaded(i,j) + road_empty(j,i) + R_j. Existing ceil relationship, capacity, trip caps and objective stages unchanged; both selection strategies consume the same matrix. Road legs and routeRef still refer to the network only; assignments expose the separate internal term. Internal motion does not make an unreachable pair reachable. `sameNode` still marks identical road nodes, not zero total length. Explicit null/absent internal motion is omitted from objective (road-only model component, not a verified zero); mixed known/unknown warns. Motion time uses same uniform scenario speed for all modeled distance, not measured site speed/service time. No source-side connectors or internal topology model. Matrix cache includes internal length with explicit null/absence distinction, matrix hash includes changed pair costs and legs. Independent checker verifies R_j, sum of legs and aggregate distance. Fingerprint model discriminator changes to fixed-charge-mm-v1.2-intrasite only for new-field requests; old road-only fingerprints and historical demo remain unchanged. Synthetic reversal: 5 m³, Q=2, near road roundtrip 2 km and far 4 km; three trips → 6 vs 12 km. Near R=3 km per trip, far R=0 → 15 vs 12 km, ranking reverses. Polygon and real geometry/measurement still open.

### v4.5 A12a: intermediate phase durability
Python publishes a private checkpoint after a proved U phase, and for unified selection after a proved L phase, before beginning the next MILP call. The checkpoint includes allocation, selected indices and completed stages, plus a pending `time_limit` stage with null bound/value/gap. Node retains the latest checkpoint per request, returns it only on the hard deadline and kills the child; explicit cancellation discards it. The normal independent JS allocation/configuration verifier still runs, recomputing U/L and checking any reported proof. A worker failure or malformed checkpoint remains an error; a checkpoint can never advance a proved rank. No in-solve SciPy callback or new optimality guarantee. This is not a change to the objective or distance units.

## v4.7 / A12b — certified bounded enumeration

Optionally sort the same fully enumerated admissible configurations by lower bound, then solve with the same two-phase fixed allocation. Let effective capacity `B_j = min(C_j, Q*T_j)` with absent trip cap treated as unbounded **only in this relaxation**. For each source `b_i = sum(B_j)` over compatible reachable sites. Every feasible solution has `U >= U_lb = max(0, sum_i max(0,D_i-b_i), sum_i D_i - sum_j B_j)`. The two expressions are lower bounds: each ignores some shared constraints; taking their maximum retains validity.

When `U_lb=0`, set `L_lb = sum_i ceil(D_i/Q) * min_j L_ij` over reachable positive-capacity sites, for positive demand. This distance bound is conditional on `U=0`: every fully served source needs at least ceil(D_i/Q) trips; each costs at least its cheapest available pair. If actual U>0, the lexicographic tuple is already worse regardless of L. If `U_lb>0`, use `L_lb=0` (distances nonnegative). Thus `(U_lb,L_lb,configurationId)` never exceeds the true best lex tuple. All lengths are exact integer mm within the existing 1e13 conservative objective budget.

Sort bounds in the same `(U,L,JSON sorted IDs)` order as final scores. Only when K eligible, **optimal** incumbents exist, and all evaluated configurations are proved, can the algorithm discard a suffix whose smallest bound is >= the current worst retained score. An ID comparison resolves equal U/L safely. `requireAllServed` only filters exact/partial solutions as in enumeration; no heuristic exclusion. Exact status still requires complete policy enumeration and accounting `proven + prunedByBound = configurationsTotal`; partial list never suffices. No pruning from incomplete solve. Complexity O(M*I*J + M log M) bounds/sorting for M enumerated sets, plus fixed MILP solves for unpruned sets; worst case all M solved.

To strengthen the fixed MILP only in the opt-in bounded strategy, after proving U=0 add `sum_j n_ij >= ceil(D_i/Q)` for each positive source. This is redundant for integral feasible solutions but removes fractional-trip relaxation points. Divide distance objective by exact common divisor of costs (no rounding), canonicalize native integer objective values within 1e-5 *native* units before multiplying back to mm, preserve raw dual bounds, and reject larger deviations. Independent verifier remains unchanged and recomputes exact mm. The initial unscaled cut experiment failed objective verification and was not accepted.

Tests: `tests/v47-bounds.test.mjs` independent per-unit oracle (72 cases, seed470719), parity, ties, timeout/cancellation, city regressions and public integration. Three measured 20×30 seed719 runs: 16/378 solved, 362 proved dominated, exact Top-5; see `benchmarks/v47/`. The previous unified and default enumeration strategies remain available, unchanged. Large catalogue beyond enumeration budget still needs unified or other proof methods.

Non-pruning reference: all 378 configurations solved via separate nested-pair enumeration and same fixed MILP in 29.575 s, all five ranks match. See `benchmarks/v47/complete-reference-final/reference.json`. Distinct from small independent integer oracle.
